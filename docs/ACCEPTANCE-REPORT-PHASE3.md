## 七、本轮确立的五条硬规矩

1. **验收五件套**：命令名 + 分文件明细 + 原行 + 运行时刻 + HEAD sha。**缺一项就不是证据**——工作区读数不属于任何 commit，不可验收。分文件明细是必需的：总数 26 可能是「9+16+1」也可能是「10+15+1」，后者意味着有断言被删。
2. **先确认 HEAD 与 git 干净，再看原行**。顺序不能反：「干净的仓库跑出 29」与「脏工作区跑出 29」是不同结论。
3. **断言的名字必须等于它实际检查的内容**。名为「仍在池中」实际查「告警发了没」，正常路径同向，一次变异就分家。
4. **每类断言至少注入一种「数值变了但结构没变」的错法**；四档常量则须**逐档各注入一次**，验一档不能代表四档。
5. **变异注入必须在独立 `git worktree` 中进行，测完删除**；变异实验期间，任何人不得把主控工作区状态当作读数。**不得用 `git stash` 移走他人未提交的成果来换取干净工作区。**

**判断一次红灯有没有价值**：看那条断言**本来该不该失败**，而不是看它是不是恰好在改文件期间出现。断言写错造成的假红，会把正确的代码改坏。
