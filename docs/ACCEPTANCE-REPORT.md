## 3. 功能验收（逐项实测）

### 3.1 三屏流程
- 首页渲染正常，显示「档案 12 / 题目 10 / 维度 06」，无控制台错误
- 答题页：题目、选项、进度条（10%）正常；选择后 `aria-pressed` 正确切换
- 结果页：主匹配人物卡、六维条形、次匹配、分享按钮全部渲染

### 3.2 六维匹配引擎
**确定性**：同一输入连续执行两次，输出**逐字节完全一致**（`diff` 无差异）。

**数学正确性**：手工复算奶龙 HX 维度——
```
x=1.00, μ=0.95, σ=0.15
g = exp(-(1.00-0.95)² / (2×0.15²)) = exp(-0.055556) = 0.945959
程序输出 g = 0.945959  ✓
ωg = 0.212 × 0.945959 = 0.200543  ✓
M = Σωg/Σω = 0.898863 / 0.928000 = 0.968602  ✓
```

**可复算性**：`src/engine/example/run.ts` 输出完整中间链路
`x_d → raw → μ → σ → g → ω → ωg → Σωg → Σω → M → β → M′ → 百分比`，
配合 `src/engine/ENGINE-CALC-EXAMPLE.md`，任何人可手工验算。

**阈值口径**：全部为第一阶段 `06`/`05` 的**设计值**，代码注释与文档均已标注，未写成实测值或行业标准。

### 3.3 结果页六维显示（P0 修复验证）
发现并修复的缺陷：前端曾自造 `normalizeDims()` 二次归一化，把引擎已算好的 0–100 分压平到 50 附近。

| | 修复前 | 修复后 | 引擎基线 |
|---|---|---|---|
| 同一 `?r=` 作答 | 52/51/52/51/51/49 | **100/81/100/100/73/21** | **EE 100 · ST 81 · AC 100 · HX 100 · RB 73 · SR 21** |

修复后**逐项吻合**。修复方式：删除前端二次归一化，改为直接消费 `result.user.x[d] * 100`，恢复「引擎是唯一算分来源」。

### 3.4 分享链接
- `?r=<base64url(答案对)>` 链接**直接打开结果页**，主匹配、次匹配、六维全部正确渲染，无控制台错误
- 实现只编码**作答**、不编码结论——结论由当前数据重算，避免「链接里的结论」与「当前引擎」不一致
- 坏 token 一律返回 `null` 并降级到首页，不向用户抛错

> **语义边界（必须写入对外说明）**：分享链接的语义是「**用当前数据重放这份作答**」，不是「锁定当时的结论」。数据更新后同一链接可能得出不同结果，这不是缺陷；对外文案**不得**写「永久有效」或「别人看到的和你完全一样」。

## 5. 遗留问题

1. **`pnpm validate` 脚本缺失**：目前必须手写 `pnpm exec tsx data/validate-data.mjs`。建议在根 `package.json` 加 `"validate": "tsx data/validate-data.mjs"`。
2. **2 个 E2E 用例待启用**：分享链接的自动化断言。
3. **校验脚本的运行方式依赖 tsx**：裸 node 会 `ERR_MODULE_NOT_FOUND`，这是刻意的失败优先设计，但要在 README 里写明。
4. **`build` 链路不含前端类型检查**：`vite build` 不查类型，`tsc -p tsconfig.api.json` 只查后端。理论上前端类型错误可混入生产产物（本轮已实际发生过两次）。建议 `build` 前置 `typecheck`。
5. **分享链接的语义边界**需写入对外文案规范。
